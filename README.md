# 果皮分舱进厂、称差裁决与分方出账

资料对应一车果皮在两个厂点的分舱交接。装车舱单、磅房报文、仓班记录和合作协议由不同业务方维护。所有组织、资料、金额和业务回执均为合成。

完整数据口径见[《磅房交换格式》](交换记录.md)。输入使用 UTF-8 JSON，资料原件均为 UTF-8 文本。

环境使用 CPython 3.11 标准库，无需安装第三方依赖。

## 交接服务（handover 包）

`handover/` 把分方交换材料落地为一套进厂交接服务，门卫、仓班、合作社、承运方、财务、协调员与仲裁员各按权限提交凭据、领取办事结果。

| 模块 | 职责 |
| --- | --- |
| `models.py` | 不可变凭据与服务产物（舱单、磅房、仓班、争议、裁决、对账单、调整单） |
| `store.py` | 追加式凭据登记，更正链与全部历史事实保留 |
| `weights.py` | 共同有效总重、单舱有效实称优先、申报重量分摊、矛盾重裁 |
| `receiving.py` | 交接地点顺序、封签核验、待核实区/隔离区、临时领用上限与领用禁令 |
| `disputes.py` | 称差与封签争议、双方认可处置、仲裁员裁决与定稿 |
| `billing.py` | 合作社原料款、承运人运费、签认冻结、补收/冲抵调整 |
| `views.py` | 七类角色的权限视图 |
| `service.py` | 统一门面，按来源权限接收凭据并串联用例 |
| `loader.py` | 按《磅房交换格式》从 JSON 目录装载交换材料 |
| `report.py` | 命令行状态报告 |

### 落地的关键业务口径

- 同一运输段按实物舱次选择交接地点，上一处实际卸完的舱不能被下一厂接收，同舱不重复接收。
- 封签一致且仓班确认的原料进待核实区；封签不符即使称重已对上也只能隔离，须经双方认可或仲裁员裁决才能放行或拒收。
- 临时领用上限按舱取合同上限与本厂实际到账数量的较小值；新核实重量低于已领用量时下领用禁令，历史领用去向保留，不抹账凑平。
- 单舱独立有效实称优先保留且可独立出账；无单舱实称的舱按申报重量在共同总重余量内分摊，隔离舱先按申报比例剥离且不形成结算重量。
- 已核实舱重合计超过共同总重时整组凭据矛盾：不削减有效实称凑总重，不新增领用、不结清相关原料款。
- 只有争议涉及的款项暂缓，同车不同争议范围独立出账；封签争议与称差可并存。
- 已签认对账单明细冻结，后续重量裁决或接收地更正只生成补收/冲抵调整单，付款方不重付原账。
- 运费按有效首卸一处与其余有效停靠每处一项认定，同一处多舱只计一个停靠。
- 各方只能看见自己有权的证据与金额；协调员视图把收货、领用、待裁议题和账单联系到同一运输段。

### 角色与身份前缀

`gate/<厂点>` 门卫、`site/<厂点>` 仓班、`coop/<合作社>` 合作社、`carrier/<承运方>` 承运方、`finance` 财务、`coordinator` 协调员、`arbiter/<仲裁员编号>` 仲裁员；装车方来源以 `ORIGIN` / `origin/*` 身份提交。

## 命令

```sh
# 运行全部核查（格式核对 + 交接规则 + 争议生命周期 + 权限边界）
python3 -m unittest discover -s tests -v

# 协调员视角的当前状态报告
python3 -m handover.report inputs

# 各角色权限视图
python3 -m handover.report inputs --actor site/FAC-A
python3 -m handover.report inputs --actor coop/COOP-F
python3 -m handover.report inputs --actor carrier/YS2
python3 -m handover.report inputs --actor finance
python3 -m handover.report inputs --actor gate/FAC-B
python3 -m handover.report inputs --actor arbiter/XU-40
```

> 处理下载来的不可信交换目录时，建议把输入目录与代码目录隔离，并用 `python3 -I` 配合显式路径运行，避免输入目录中的同名模块被解释器加载。
